High level · IaC independent

Vend a usable service, not an empty stack

Teams request an observability environment. A platform-owned recipe turns that request into a configured Grafana Cloud stack and a clear operating contract.

The concept works with Terraform, Crossplane, API automation or another delivery engine. Ongoing drift repair and rotation depend on the chosen implementation; a one-time API call does not supply them automatically.

Evidence: Repository concepts; Grafana Cloud stacks.

Mid level · Capability map

What can the machine vend?

A stack is the starting point. The useful service includes access, content, collection and operations, selected according to workload needs and platform policy.

These are resource families in this reference, not a promise that every stack receives every feature. Workload targets, credentials, people, product availability and entitlement remain prerequisites.

High level · Operating model

Provisioning is one stage of the service

Keep the intake, policy, provisioning, operations and retirement responsibilities explicit, whichever IaC tool runs the recipe.

Identity settings differ beyond the provider name

  • UK / Entra ID: dedicated application registration, tenant-specific authorization/token endpoints, UK group claim mapping, strict role mapping and a separate secret reference.
  • Germany / SAML: market IdP metadata, entity/ACS configuration, assertion attribute mappings, signed assertion policy and group-to-team bindings.
  • France / Okta: market application, issuer/endpoints, scopes, allowed groups, role mapping and credential references.
  • Poland / generic OAuth: market endpoints and client registration, group and role claim paths, scopes and login admission rules.

Changing IdP type is a migration requiring login and rollback validation. Profile labels alone do not create IdP registrations.

A common telecom dashboard pack

  • Every market: NOC overview, ingest health, platform usage and service availability.
  • RAN: site availability, radio-access latency, handovers and saturation.
  • Core: registration/session success, signaling and packet-core performance.
  • Fixed: access-network and broadband service health.
  • Digital: customer application latency, errors, frontend signals and journeys.
  • Security: SOC data views with explicitly reviewed access.

These telecom packs are proposed content, not dashboards shipped by this reference. Queries need market-owned metrics, labels and data sources.

Mid level · Telecom access model

SSO, RBAC and LBAC solve different problems

Authenticate a person, map their groups to market teams, grant actions and content access, then apply data filters on the supported data-source query path.

Do not use dashboard variables or folder permissions as a data-security boundary. LBAC is not cross-stack federation. Ensure Query access and team rules cover the intended users: current docs say no matching team rules can leave logs/metrics queries unrestricted. Backend, credential and product constraints still apply.

Evidence: Authentication; RBAC; LBAC; reference renderer.

Mid level · This Crossplane reference

Three ownership roles, one desired state

Argo CD syncs platform definitions and request objects. Crossplane composes the child resources. The Grafana provider reconciles those children against Grafana Cloud.

Argo CD must not also declare Crossplane-generated children. ESO owns secret materialization and publication, shown separately. Only enabled/* is watched; the catalogue remains inert until an adopter deliberately enables a request.

Evidence: Architecture; composition function; ApplicationSet.

Mid level · Bootstrap resources

One request expands into a dependency graph

The core renderer creates a stack, bootstrap account and credential chains. Stack-local content and optional modules become eligible as their observed prerequisites are satisfied.

This is a collapsed dependency view. Policy tokens also publish through ESO; admin tokens do not flow into telemetry collectors. Provider-assigned identities are observed, never derived. Readiness is evidence from controllers, not a guarantee inferred from rendering.

Evidence: core stack renderer; stack orchestration; Fleet chain; secret handoff.

Mid level · Credential ownership

Secure handoff is part of the product

ESO publishes generated bootstrap credentials to an external store and reads back the stack-local provider credential. Consumer telemetry credentials use a separate policy and publication path.

Organization credentials enter through their own ExternalSecret and organization ProviderConfig before this chain. That input is omitted here. Human SSO credentials are separate. Never place bearer tokens in requests, Git, diagram labels, status or logs.

Evidence: Secrets; credential bridge implementation; example secret-store integration.

Mid level · Telecom recipe comparison

A shared baseline does not mean identical stacks

Each market selects approved local configuration while inheriting a versioned common service baseline. The same pattern is repeated for all sixteen stacks.

Conceptual recipe composition, independent of IaC. In this repository the adopter encodes the baseline in platform configuration and explicit module requests. There is no built-in telecom profile API, automatic profile-merging service or shipped telecom dashboard pack.

Evidence: Platform configuration; SSO profiles; module inputs.
